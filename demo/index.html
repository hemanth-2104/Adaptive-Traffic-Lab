What the system implements
1 · Visual encodingFrozen Qwen2.5-VL-3B; final prompt-token hidden state.
2 · Latent refinement256-dimensional projection and three shared GRU updates.
3 · Predicted scene factsSeparate JSON extraction into a NetworkX graph.
4 · Conservative verificationQuestion-specific rules; unknown facts disable checks.
At each recurrent step, the projected image-question vector is the input and the previous recurrent state is the hidden state. Cross-entropy trains only the projection, recurrent cell, and answer head. Model selection uses validation macro-F1.
Read results with these limits
The 240-frame pilot samples at most one binary question per category per frame. It is not the complete DriveLM benchmark. The test subset contains only one supported proceed question, so safety-action conclusions are not supported. Most covered checks concern object taxonomy and relevance.
Rules operate on model-predicted facts and can enforce an incorrect observation. Higher rule satisfaction is not proof of answer accuracy, internal reasoning faithfulness, or vehicle safety. The results report both beneficial and harmful corrections.
The explore view defaults to a validation-selected ensemble and advisory checking. Automatic correction is an explicit demonstration option. It recomputes trained classifiers from a real cached VLM representation. Single-head demonstrations use seed 18; the ensemble averages seeds 18, 42, and 572. What-if facts are clearly marked and do not change saved results. No simulated data is mixed into empirical benchmark results.
